# 商用化の検討資料

「個人情報を AI に渡さない」という課題に対する製品として、
どのように価値を出し、どう売るか。技術判断と市場判断を分けて整理します。

---

## 1. 誰の、どんな問題を解くか

### 一次ターゲット

| セグメント | 痛み | 支払い意欲 |
|---|---|---|
| **中小企業のバックオフィス**（法務・人事・経理） | 顧客情報を含む文書を AI に貼れない。規程で禁止されている | 中〜高 |
| **士業**（弁護士・税理士・社労士） | 依頼者の機微情報を扱う。守秘義務がある | **高** |
| **医療・介護** | 患者情報。要配慮個人情報 | 高（ただし導入障壁も高い） |
| **個人開発者・フリーランス** | 受託先の情報を AI で扱いたいが、リスクを取れない | 低〜中 |
| **AI を業務導入したい企業の情シス** | 「禁止」ではなく「安全に使わせる」仕組みが欲しい | **高** |

### 競合との違い

| 手段 | 問題 |
|---|---|
| AI 利用を禁止する | 生産性が上がらない。現場が隠れて使う |
| 手で伏せ字にする | 続かない。漏れる |
| クラウド型のマスキングサービス | **原文をそのサービスに渡す必要がある**（本末転倒） |
| 本製品 | **原文が端末から出ない。** 転送先も選べる |

**最大の差別化は「ローカル完結」です。** これは技術的制約ではなく、
「原文を預からない」という製品思想です。

## 2. 価格設計の選択肢

### A. 買い切り（永久ライセンス）

| 項目 | 案 |
|---|---|
| 個人 | ¥4,800 |
| 法人（5 台） | ¥24,000 |
| 法人（20 台） | ¥78,000 |

- **利点:** ローカル完結の思想と整合する。「監視されない」安心感
- **欠点:** 継続収益が無い。サポートコストが重い

### B. サブスクリプション

| 項目 | 案 |
|---|---|
| フリー | ルールベース検出、1 セッション |
| Pro（個人） | ¥780/月 — NER、無制限セッション、辞書更新 |
| Team（5 名） | ¥4,800/月 — 管理機能、監査ログ |
| Business | 要相談 — SSO、ポリシー配布、優先サポート |

- **利点:** 継続収益。辞書・モデル更新の対価として説明しやすい
- **欠点:** 「ローカル完結なのにサブスク？」という心理的抵抗

> **推奨: ハイブリッド。**
> アプリ本体は買い切り（または無料）とし、
> **検出辞書・モデルの更新**と**法人向け管理機能**をサブスクにする。
> 「あなたのデータは送られないが、精度は最新」という説明が成立します。

## 3. 商用版で追加すべき機能

### 無料版と有料版の線引き（案）

| 機能 | 無料 | Pro | Business |
|---|---|---|---|
| ルールベース検出 | ✅ | ✅ | ✅ |
| NER 検出 | — | ✅ | ✅ |
| セッション数制限 | 1 | 無制限 | 無制限 |
| カスタム語辞書 | 5 語 | 無制限 | 無制限 |
| 監査ログ | — | — | ✅ |
| ポリシー一括配布 | — | — | ✅ |
| SSO / SAML | — | — | ✅ |
| 優先サポート | — | — | ✅ |
| 辞書更新 | — | ✅ | ✅ |

### 法人向けに必要な機能

1. **配布と更新** — MSI / PKG、自動更新、社内配布
2. **ポリシー管理** — 「この種別は必ずマスク」を管理者が固定し、ユーザーが OFF にできないようにする
3. **監査ログ** — 「いつ・誰が・何件マスクしたか」（**原文は記録しない**）
4. **除外設定** — 社内の許可ドメイン、内部 LLM への転送
5. **一括ライセンス管理** — 台数管理、オフラインライセンス

## 4. 技術的な商用化課題

| 課題 | 現状 | 対応方針 |
|---|---|---|
| デスクトップ GUI | 雛形のみ（未ビルド） | Rust 環境でビルド検証 → 署名 → 公证 |
| インストーラ | 未整備 | Tauri Bundler + WiX / create-dmg |
| 検出精度の定量 | 主観的 | 日本語 PII の評価セットを作り、再現率・適合率を公表 |
| NER の同梱 | 別途インストール | 軽量モデルの同梱、またはオプション DL |
| 性能 | 未計測 | 実測ベンチマーク（1 リクエストあたりの遅延） |
| 更新配信 | 無し | Tauri Updater + 署名鍵 |
| ライセンス認証 | 無し | オフライン検証可能な署名ライセンス |

### 遅延の見積り（要実測）

プロキシはリクエスト本文を走査するため、必ず遅延が乗ります。

- ルールベースのみ: 数 ms〜数十 ms 程度（本文長に依存）
- NER を有効化: 数百 ms〜1 秒程度（モデルと文長に依存）

**「AI の応答を待つ時間に比べれば誤差」** と言える範囲に収める必要があります。
NER は既定 OFF、長文では文単位で分割するなどの対策を検討します。

## 5. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| **検出漏れ** | 最重大。信用を失う | 「完全ではない」ことを明示。`redact_only` モード、検出プレビュー、統計を提供 |
| 過剰マスクで AI の回答が劣化 | 体験の悪化 | 種別ごとの ON/OFF、カスタム語、検出プレビューで調整可能に |
| 上流 API の仕様変更 | 動作停止 | OpenAI / Anthropic 互換の狭い範囲に依存。透過的なパススルー設計 |
| 競合（大手の類似機能） | 価格競争 | ローカル完結・日本語特化・可逆復元で差別化 |
| 法的責任 | 賠償リスク | 免責事項の明記。SLA は Business のみ |
| OS の API 変更 | メンテ負荷 | Tauri は追随が早い。依存を薄く保つ |

**最も重要なメッセージング:**
> 本製品は「個人情報の漏洩を保証して防ぐもの」ではありません。
> **「AI に渡す前に、気づかず渡してしまうリスクを大幅に下げるもの」**です。

この誠実さが、結果として最も強い販売力になります。

## 6. 市場投入の段階

### Phase 1: OSS として公開（現在）

- MIT で公開し、技術的信頼を獲得
- フィードバックから検出精度を改善
- GitHub Stars が社会的証明になる

### Phase 2: デスクトップ製品化

- 署名済みインストーラ
- 無料版 + Pro ライセンス
- 日本語のドキュメントと導入ガイド

### Phase 3: 法人向け

- ポリシー管理・監査ログ
- 導入支援・サポート契約
- 業界別の辞書パック（医療・法務）

### Phase 4: 拡張

- ブラウザ拡張（ChatGPT / Claude の Web UI 入力フック）
- オンプレ LLM への転送プリセット
- 英語・中国語・韓国語対応（同じ設計で言語パックを差し替え）

## 7. 最初にやるべきこと

優先順位順:

1. **Rust 環境で `cargo check` を通す** — 製品の「顔」が動かないと話にならない
2. **日本語 PII の評価セットを作る** — 「精度 92%」と言える根拠
3. **遅延を実測する** — 「体感に影響しない」ことの証明
4. **macOS のメニューバー常駐を完成させる** — 一次ターゲット（士業・バックオフィス）は Mac 比率が高い
5. **導入事例を作る** — 1 社でも「これがあるから AI を使えるようにした」事例

---

## 8. 現実的な見通し

- **技術的完成度:** 中核（検出・マスク・復元・プロキシ）はテスト済みで実用域。
  GUI と配布が未整備
- **差別化:** ローカル完結 + 日本語特化 + 可逆復元は明確な強み
- **最大の障壁:** 技術ではなく「配布」と「信用」。
  署名・公証・サポート体制・導入事例に投資が必要
- **最初の顧客:** 士業、または AI 導入を進めたい中小企業の情シス

**単独での事業化は可能ですが、営業とサポートの工数が技術以上に必要になります。**
OSS としての評判を足がかりに、法人向けサポート契約から始めるのが
最もリスクの低い入口です。
